# Unity Code Reviewer

## Overview
This skill performs a rigorous verification of Unity project changes. It ensures that the recent codebase changes align with the documented project plan (`PLAN.md`) and task descriptions (`TASK.md`). Furthermore, it actively performs static code review to catch logic errors or Unity-specific defects, and strictly executes a build/compile test using `unity-cli` to guarantee the project remains error-free.

## Language Constraint (한국어 강제)
**CRITICAL:** All responses, code review reports, explanations, and outputs generated by this skill MUST be written entirely in Korean (한국어). 어떠한 상황에서도 무조건 한국어로만 답변하고 보고서를 작성해야 합니다.

## Workflow

When triggered, always follow these sequential steps:

### 1. Context Gathering
- Read the entire `PLAN.md` file in the project root to understand the overall project architecture and goals.
- Read the entire `TASK.md` file to understand the specific requirements of the current task.
- Review recent changes or diffs to understand the code that has been modified. Check the implementation details against the tasks.

### 2. Static Code Review
- Carefully analyze the added or modified scripts.
- Look for common Unity pitfalls:
  - Inefficient use of `Update()` or `FixedUpdate()`.
  - Memory allocations in tight loops.
  - Improper serialization or reference handling (e.g., missing `[SerializeField]`, null reference risks).
  - Race conditions in asynchronous code or coroutines.
- Compare the logic directly to the requirements outlined in `TASK.md`. Ensure no requirements were missed or incorrectly implemented.

### 3. Compilation and Build Verification
This is a mandatory step. You MUST verify the project using the Unity CLI to ensure no compilation errors or build failures exist.

- **Action:** Run the compilation and build process using the workspace's `unity-cli` command.
- Use the `run_shell_command` tool to execute `unity-cli` (for example, `unity-cli compile` or `unity-cli build`, depending on the user's specific package/environment).
- If the exact CLI command or its parameters are not provided by the workspace configuration, use standard Unity CLI invocation (e.g., `<UnityPath> -quit -batchmode -projectPath . -buildTarget <Target>`) or `.NET` build commands if appropriate (e.g., `dotnet build` for script compilation only).
- If the command fails or errors are produced, capture the stdout/stderr.

### 4. Reporting & Error Correction
- If there are build or compilation errors, propose surgical fixes and, if the user allows, apply them and repeat the build validation process until successful.
- Once compilation and build checks pass, output a structured code review report.
- Include a **"Plan & Task Alignment"** section.
- Include a **"Static Code Review"** section highlighting any logic errors or defects identified.
- Include a **"Build Validation"** section detailing the successful outcome of the `unity-cli` compilation/build process.

### 5. Code Review File Generation
- **Action:** Create or update a file named `Code_Review.md` in the project root directory.
- **Content:** Write the complete code review report (from Step 4) into this file.
- **Language:** Ensure the entire content of `Code_Review.md` is written entirely in Korean (한국어).
- If the file already exists, overwrite its content with the new report. This ensures a persistent record of the review is available in the codebase.
